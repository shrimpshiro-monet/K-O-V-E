# Mirror P0: EditDNA v2 and measured refinement

EditDNA stores no reference pixels/audio. Version `kove.mirror.v2` uses reduced rational `fps: {num, den}`, explicit `fpsSource`, integer `durationFrames`, half-open shot/caption intervals, and frame-indexed motion. `rhythmCurve` is in frames. Convert at media/timeline boundaries via `frameToSeconds` and `secondsToFrame`. V1 numeric FPS was not measured: `mirror_reference_1to1` requires an explicit `confirmedLegacyFps` for migration.

Desktop packages ffprobe alongside FFmpeg; the probe returns average/nominal FPS, stream duration, coded dimensions, sample aspect ratio, and rotation. Conflicting average/nominal FPS is marked variable and does not become an authoritative clock. Browser HTML video exposes duration/display dimensions but not authoritative FPS. The reference UI therefore requires an explicit rational FPS selection when desktop ffprobe is missing or reports unknown/VFR. References up to 600 frames use every indexed decoded frame for cuts when WebCodecs/Mediabunny is available; longer references use sparse candidates (rapid cuts may be missed), then search each candidate interval by frame. Decoded sample timestamps and durations are checked against the selected CFR clock. The HTML-video capability fallback may not decode exact requested frames and is marked in DNA warnings; verify critical cuts manually.

`mirror_refine` samples decoded reference frames and composited timeline renders on the EditDNA clock; it searches editable motion/LUT knobs, restores the best state, and returns measured grayscale SSIM, rhythm DTW, trial history, seed, sample frames, and frame rate. LPIPS is reported only when a real model callback is configured. No renderer/decoder means `UNSUPPORTED_HOST`, not a fabricated score. The browser keeps the reference Blob ephemerally outside the project. Headless hosts can supply `mirrorFrameRunner`; `@kove-advanced/agent-runner` offers `createFfmpegMirrorFrameRunner({referencePath, renderTimelineVideo, ffmpegPath?})`, which decodes actual frame N from reference and **freshly rendered current-state** timeline video. This adapter requires FFmpeg and a real compositor callback; it is not a bundled standalone compositor. Exact numbered-frame decoding is deliberately slower on long sources. There is no bundled LPIPS model.

For headless Mirror v2, `runHeadlessEdit({ mirror: { referencePath, mediaPaths: { [mediaId]: filePath }, ffmpegPath?, chromiumExecutablePath? }, ... })` enables the existing `mirror_refine` tool without changing its frame callback. `createCompositorMirrorFrameRunner` is also available for an externally managed `HeadlessHost`; always call `close()` in `finally`. The reference remains FFmpeg numbered-frame rawvideo. Every timeline sample exports a version-tagged project JSON snapshot, binds the referenced visual media as private immutable byte buffers, hashes project JSON plus media bytes (SHA-256), and sends the snapshot into a reused Playwright Chromium page running the core `VideoEngine.renderFrame`. Its browser cache key is `(snapshotHash, timeSeconds)`; changing trial actions or media bytes invalidates the old engine/frame cache. Only checked 64×64 luma bytes return to the critic, not PNGs. Missing media/decoders fail explicitly. This local browser harness runs through Vite and requires a Chromium executable and FFmpeg; the older `createFfmpegMirrorFrameRunner` export remains for existing video-export callers.

`packages/agent-runner/src/mirror-compositor.test.ts` generates local FFmpeg source material and exercises an actual browser compositor image frame, a decoded WebM video clip, and two `mirror_refine` trials over distinct snapshot hashes at `30000/1001` FPS. On the scratch Linux Chromium/FFmpeg setup, the image/reference SSIM was `0.999384605476097`; after replacing the project with a red background it was `0.014698314172719332`. One measured refinement produced sampled frame `[14]` and best-score history `[0.8090953077922358, 0.8154928080082164]`. Scores are run-specific and are not claims of broad perceptual parity. Re-run with `FFMPEG_PATH=/path/to/ffmpeg CHROMIUM_EXECUTABLE_PATH=/path/to/chromium pnpm --filter @kove-advanced/agent-runner exec vitest run src/mirror-compositor.test.ts`; without either executable the named test cases skip. The scratch Chromium required its own NSS libraries via `LD_LIBRARY_PATH=/tmp/al2023/lib` in this environment. The effect/transition goldens ran locally against scratch FFmpeg and Chromium: 63/63 passed after using a transparent generated stimulus for shadow/glow and a real `scanlines` shader ID. CI installs FFmpeg and Playwright Chromium when the billing lock is lifted; CI itself has not been confirmed. Packaged desktop binaries on every architecture and frame-accurate seeks for arbitrary real-world sources remain unverified.

## v2.1 — peak cut refinement and camera fallback checks

- `refineCutFrameByPeak` in `packages/core/src/mirror/cut-boundary.ts` scans every adjacent pair in `[previousFrame, frame + 1)` and selects the strongest difference, not the first threshold crossing. The first-crossing `locateCutFrame` stays available unchanged and is deprecated **for shot-boundary selection only**. Ties choose the earliest peak. A non-finite difference fails rather than manufacturing a boundary.
- The web extractor retains its normalized sampled-RGB signal and threshold `0.23`. A coarse endpoint crossing with no adjacent difference above that threshold is still placed at its peak, but now produces a lower-confidence gradual-transition warning in the **same** `ReferenceProfile.warnings` array used for HTML-seek and sparse-decoding limitations. HTML video seeking is still not frame-accurate; an indexed, timestamp-verified decoder is required to claim an exact frame. Multiple independent cuts between two coarse samples can still collapse to the strongest one. Switching to 64×64 luma and re-deriving its threshold are **deferred**.
- `ShotProfile.cameraMotion.samples` remains the canonical frame-indexed motion measurement. Its existing `dominantMove` is derived from samples for v2 compatibility; no sibling `camera` field is added. The installed OpenCV.js runtime types `estimateAffinePartial2D` but does not export it at runtime. `hasNativeAffineEstimator` probes the actual function and warns once when absent; the extractor continues using its pre-existing deterministic JS LK/RANSAC/least-squares partial-affine fit regardless of that capability. Synthetic translation, scale, rotation and mixed-transform tests exercise that **same** fitted math and a point-tracking RANSAC path with an outlier. This does not yet validate per-frame motion recovery from generated video.
